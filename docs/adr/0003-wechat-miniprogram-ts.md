# 平台：微信小程序 + TypeScript

选定平台为**微信小程序**，语言 **TypeScript**。ADR-0002 的「纯游戏内核 + 可插拔传输」架构在此平台上完全成立：内核是纯 TS，被小程序端与未来云函数共同复用。

理由：小程序分发零摩擦（微信内打开即玩、免应用商店）、社交分享天然适配「找对手」；TS 内核与 ADR-0002 一致，可跨端复用。

## v2 联机：倾向微信云开发（修订 ADR-0002 的服务器预期）

ADR-0002 原预期 v2 自建 Node 服务器；在微信小程序下，更优路径是**微信云开发**：

- **云函数**（Node 运行时）可直接 import 同一份 TS 内核，做服务器权威校验与走法广播。
- **云数据库**存对局状态 / 走法日志，支持断线重连。
- 身份用微信 **openid**，**免自建账号体系**。

这把联机的门槛（服务器、账号、运维）大幅降低。具体协议待 v2 启动时另立 ADR。

## 影响

- v1 本地 AI 搜索在小程序 JS 线程运行；本棋规模小，主线程 + alpha-beta + 深度上限即可，必要时用 Worker。
- 走法 command 须可序列化（已在 ADR-0002 要求），云开发同步直接复用。
- 棋盘绘制用 Canvas 2d（自定义 9 点 / 线 / 箭头 / 棋子）。

## UI 外壳

- 决定采用**原生开发（WXML/WXSS + TS）**。理由：最直接、抽象层最少、Canvas 2d 画棋盘最顺；即便日后要多端，纯内核是 TS 可直接搬走，仅重写外壳，低遗憾。跨端框架（Taro / uni-app）仅在未来明确要同时上多端时再考虑。
