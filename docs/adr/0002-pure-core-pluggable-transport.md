# 架构：纯游戏内核 + 可插拔传输层（v1 本地，v2 联机）

v1 范围为**同设备双人轮流 + 单机 AI**；联机对战因需服务器、账号、匹配、实时同步、断线重连等，放到 v2。为使联机日后可作为「增量」加入而非重写，我们将**游戏规则与状态管理抽成无 UI、无网络依赖的纯确定性内核**，AI 与传输层都构建在其上。

理由：纯内核可被本地 UI、AI 搜索、未来服务器三方复用，规则只写一份；传输层抽象后，本地模式与联机模式只是不同的「传输实现」。

## 分层

- **Game Core（纯内核）**：规则、合法走法生成、走子执行、胜负判定、状态快照。无副作用、确定性、可序列化。被以下三层共享。
- **AI**：基于 Core 的搜索（极小极大 + alpha-beta，与公平性求解器同源），产出走法。
- **Transport（传输层）**：统一接口为「提交走法 / 订阅对方走法」。v1 实现 `LocalPassPlay`（同设备轮流）、`LocalAI`（对 AI）；v2 实现 `OnlineClient`（向服务器发走法、收对方走法）。
- **UI**：渲染 9 点、线、箭头、棋子；把玩家输入转为走法交 Core，订阅 Core 状态变化重绘。

## 联机预留（v2 预期形态，暂不实装）

- **服务器权威 + 走法同步**：客户端提交走法，服务器用同一 Core 校验并广播（同步 command 而非全状态），防作弊且带宽小。
- **断线重连**：靠「状态快照 + 走法日志」恢复。
- 具体协议待 v2 启动时另立 ADR。

## 影响

- v1 即须保持 Core 与 UI/Transport 解耦：不能在 UI 里直接改棋盘状态，所有变更经 Core 接口。
- AI 与未来服务器复用同一 Core，规则无重复实现。
- 走法须设计为可序列化的 command（含玩家、起点、终点），为联机同步与回放/悔棋预留。
