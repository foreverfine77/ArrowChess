# 发布检查（2026-10-04）

## 结论

网页版可作为本地双人 / 人机的测试版发布。微信小游戏应先通过真机验收；好友联机暂未达到公开推广条件。未执行公网部署或微信提审。

## 本次验证与修复

- 80 项 Vitest 测试和 15 项 Node 测试通过；Core、Web、小游戏三套 TypeScript 类型检查通过。
- 修复网页发布构建：`npm run build:web` 同时更新双击使用的 `web/game.js`，并生成 `dist/web/index.html` 与 `dist/web/game.js`。发布目录不引用 TypeScript，也不依赖开发服务器。
- 用普通静态 HTTP 服务打开发布目录，浏览器成功显示棋盘与放置提示；开发入口已另行验证困难 AI 落子。
- 自动测试中的微信 SDK、数据库和事务是模拟环境，不能证明云端已经部署或具备真实权限配置。

## 网页发布

1. 运行 `npm run build:web`。
2. 将整个 `dist/web` 目录作为静态站点上传，包含网页、脚本、图标和字体许可。
3. 用实际公网链接在桌面、手机浏览器各完成一局，检查加载、落子、AI、悔棋及回放。

当前网页版没有好友联机入口，也没有对局存档；刷新网页会重置当前对局。小游戏具备本地存档。联网对局不能通过发布此静态网页启用。

## 微信联机发布前的工作

- 在实际 AppID 下确认云环境，部署四个云函数及 `makeMove/rules.cjs`，应用 `games` 数据库权限。`CLOUD_ENV_ID` 为空时使用默认环境，因此空值本身不证明部署失败，也不证明已部署。
- 两台手机验证双方放置、红/黑先手、完整终局、分享加入、断网恢复、前后台切换和旋转后的触摸；确认非参与者无法读房间、客户端不能直接改局面。
- 真机测量困难 AI 的耗时。当前性能数据来自桌面 Node，不能保证低端手机帧率。
- 公开推广前补充服务端创建房间限流和过期房间自动清理，配置费用告警并核实实时连接额度。当前每个房间限制 24 小时内操作，但数据库文档不会自动删除。
- 检查实际微信后台的账号与版本审核状态；本次没有登录后台核验或提交审核。

联机部署细节见 `docs/online-deployment.md`。自动恢复上次在线房间、断线判负等属于后续功能，不是当前已实现能力。
