# 箭棋联机：部署与成本

当前方案是微信云开发：客户端提交放置点或走法，云函数使用同一份 Core 生成权威局面，双方仅监听当前房间文档。无需购买和运维一台服务器。服务器能力仍由云服务提供，云服务可能产生套餐及超额费用。

## 开通和部署

1. 在这个小游戏 AppID 的微信开发者工具中开通云开发。选择可用的免费体验环境做双人验证，正式运行再根据用量选择套餐；本次代码修改没有购买、创建或部署任何云资源。
2. 将环境 ID 填入 `miniprogram/cloud-config.ts` 的 `CLOUD_ENV_ID`，确保客户端和四个云函数部署在同一环境。空字符串使用该 AppID 配置的默认环境。
3. 创建文档型数据库集合 `games`。在权限管理中，将 `miniprogram/database.rules.json` 的内容应用到该集合：只有房间双方可以读，客户端不能写。写入只能经过云函数。不要使用“所有用户可读写”。
4. 在项目根目录执行 `npm ci`、`npm test`、`npm run typecheck`。构建会同步共享 Core/renderer、生成小游戏 `miniprogram/minigame/game.js` 和云函数规则包 `cloudfunctions/makeMove/rules.cjs`。
5. 在开发者工具中，对 `cloudfunctions/createGame`、`joinGame`、`makeMove`、`getOpenId` 分别执行“上传并部署：云端安装依赖”。上传 `makeMove` 时必须包含生成的 `rules.cjs`。
6. 开发者工具打开 `miniprogram/project.config.json`，预览到两台手机。第一台切换“好友”模式，选择先手并创建房间，通过分享菜单发邀请；第二台从邀请进入，或点击“加入房间”输入房间号。
7. 新协议包含局面版本、开局位置和请求 ID，与旧房间格式不兼容；部署新版后重新创建房间。旧云函数也必须一起更新，不能只替换客户端。

## 双机验收

- 分别用红先手、黑先手完成双方放置、走法、反向返回及终局；双方棋子、路径、棋谱和胜者一致。
- 快速重复点击不能产生多手；两人同时尝试加入一个空位时只能一人成功。
- 断网再恢复、前后台切换，以及已运行的小游戏通过另一份分享邀请返回，均能重新同步；失败提交不提前修改实时局面。
- 确认数据库权限拒绝非参与者读取和任何客户端直接写入。代码中的权限文件是待应用的配置，不能代替云控制台验收。
- 竖屏、横屏和旋转后的触摸位置正确；本地双人/AI 关闭重启可继续上次对局。联机重新打开可通过原邀请或房间号重连。
- 检查云函数日志、实际请求延迟和监听错误。本地自动测试使用 SDK 模拟，不能证明真实环境、权限或网络已经部署成功。

## 成本与体验的均衡

截至 2026-10-04 复核，CloudBase 官方产品页列出免费体验版 0 元/月、3,000 资源点/月，以及个人版约 19.9 元/月、40,000 资源点/月（限时优惠）。微信绑定环境的套餐资格、额度和超额费用以该账号控制台为准，不能据此承诺永久免费或每月费用上限。

官方资源点价格表另列出：免费体验版和个人版的实时推送连接数均为 10，每次 watch 占用一个连接。双方各监听一次时，理论上约 5 场完整双人对局同时在线；等待房间和其他监听也会占用额度。个人版并未增加这个连接上限。更多同时对局应另行评估套餐升级或长连接服务，不能只看每月资源点数量。具体以该微信绑定环境控制台为准。

对箭棋这种回合制游戏，建议先用云函数 + 文档实时监听，优先保证合法走法、幂等提交和重连；不为每间房开常驻进程，不按帧同步棋盘，也不做每秒轮询。客户端在提交时显示确认状态，确认后应用服务端局面。云函数冷启动和弱网延迟需在真机上测量；持续低延迟需求明显时再评估长连接服务。

目前每次放置/走法调用一次云函数，事务读取并更新一份小房间文档，双方接收监听事件。加入房间和重新连接还有额外读写；监听连接时长、规则读取、函数执行、存储也可能计费。这是用量结构，不是精确账单公式。

客户端退到后台、退出房间和终局会关闭监听。房间 24 小时后拒绝新操作，但这不会自动删除文档；在控制台定期清理过期测试房间。公开推广前，应根据实际用量设置费用告警、检查创建房间频率，并评估服务端限流和自动清理；当前版本没有完整的流量滥用防护。

联机重新进入需要邀请或房间号，暂未实现“自动寻找上次房间”和断线判负；不会把本地悔棋未经双方同意同步到在线房间。当前联机悔棋和提示控件禁用。

## 本机 npm 启动异常

本机的 `npm.ps1` 错误指向缺失的用户目录文件。本次验证直接使用已安装的 npm CLI：

```powershell
node 'D:\Application\Nodejs\node_modules\npm\bin\npm-cli.js' test
node 'D:\Application\Nodejs\node_modules\npm\bin\npm-cli.js' run typecheck
```

未修改系统 npm 配置。
